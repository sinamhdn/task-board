The issue is caused by the padding (pl-1 and pr-1) on your parent container, combined with how the translateX percentage is calculated.

Why it happens (The Math)
Your container is w-48 (192px wide).

The w-1/3 slider is 33.33% of the total width, which equals 64px.

Because the slider is absolute without left-0 or right-0, its default starting position is the left padding (pl-1 is 4px).

For the "System" mode (index === 2), translateX(200%) moves the slider by 2 × its width (2 × 64 = 128px).

Final position: Starting at 4px + moving 128px = 132px from the left border.

Right edge: 132px + 64px (width) = 196px.

Overflow: Your container's right border ends at 192px, so the slider overflows by 4px (196 - 192).

On the left (index = 0), translateX(0%) starts it at 4px, which fits perfectly inside the pl-1 gap.

How to fix it
Instead of using percentages (index * 100%) which rely on the slider's width relative to the border-box, use pixel translations that account for the padding.

Change your slider style to:

javascript
style={{
  transform: `translateX(${index * 60}px)`,
}}
Why 60px?

index = 0 (Light): 0px

index = 1 (Dark): 60px (Centers it exactly)

index = 2 (System): 120px (Left edge = 4px padding + 120px = 124px. Right edge = 124px + 64px = 188px. Since pr-1 is 4px, the parent's content ends exactly at 188px. No overflow!)

Alternative (Clean Code)
If you prefer using an object, update your commented-out transformIndex with these mathematically perfect values (the 94 and 189 in your code are incorrect and would cause even worse overflow):

javascript
const transformIndex = {
  light: 0,
  dark: 60,
  system: 120,
}[theme];

// Then use it in the style:
style={{
  transform: `translateX(${transformIndex}px)`,
}}
